# Introduction to SerializedObject data binding

Get started with SerializedObject data binding.

Read time 7 minutesLast updated 3 days ago

---

You can use the SerializedObject data binding system to bind to [serialized properties](/en-us/engine/6000.6/script-reference/unityeditor/serializedproperty). This means you can bind visual elements to the following objects that are compatible with the [Serialization system](/en-us/engine/6000.6/manual/programming-environment/code-reload-serialization/script-serialization):

* User-defined [```
  ScriptableObject
  ```](/en-us/engine/6000.6/script-reference/unityengine/scriptableobject) classes
* User-defined [```
  MonoBehaviour
  ```](/en-us/engine/6000.6/script-reference/unityengine/monobehaviour) classes
* Native Unity component types
* Native Unity asset types
* Primitive C# types such as

  ```
  int
  ```

  ,

  ```
  bool
  ```

  , or

  ```
  float
  ```

  .
* Native Unity types such as

  ```
  Vector3
  ```

  ,

  ```
  Color
  ```

  , or

  ```
  Object
  ```

  .

## Value binding

You can only bind the

```
value
```

property of visual elements that implement the [```
INotifyValueChanged
```](/en-us/engine/6000.6/script-reference/unityengine/uielements/inotifyvaluechanged1) interface. For example, you can bind [```
TextField.value
```](/en-us/engine/6000.6/script-reference/unityengine/uielements/textfield/value) to a

```
string
```

, but you can't bind [```
TextField.name
```](/en-us/engine/6000.6/script-reference/unityengine/uielements/visualelement/name) to a

```
string
```

.

You can bind between an object and any visual element that either derives from [```
BindableElement
```](/en-us/engine/6000.6/script-reference/unityengine/uielements/bindableelement) or implements the [```
IBindable
```](/en-us/engine/6000.6/script-reference/unityengine/uielements/ibindable) interface.

## Create a binding

To create a binding, either [call

```
Bind()
```](#call-bind) or [```
BindProperty()
```](#call-bindproperty).

### Call ``` Bind() ```

You can call [```
Bind()
```](/en-us/engine/6000.6/script-reference/unityeditor/uielements/bindingextensions/bind) to bind an element to a [SerializedObject](/en-us/engine/6000.6/script-reference/unityeditor/serializedobject). Before you bind an element, you must [set the binding path](#set-binding-path) and create a SerializedObject.

Use this method if you don't have easy access to the

```
SerializedProperty
```

for the binding. Refer to [Create a binding with a C# script](/en-us/engine/6000.6/manual/uitoolkits/uielements/uie-data-binding/uie-editor-binding/uie-binding-examples/uie-create-a-binding-csharp) for an example.

The [```
Bind()
```](/en-us/engine/6000.6/script-reference/unityeditor/uielements/bindingextensions/bind) extension method sets up an entire hierarchy of visual elements with specified [```
bindingPath
```](/en-us/engine/6000.6/script-reference/unityengine/uielements/ibindable/bindingpath) properties. You can call the [```
Bind()
```](/en-us/engine/6000.6/script-reference/unityeditor/uielements/bindingextensions/bind) method on a single element or the parent of the hierarchy that you want to bind. For example, you can call [```
Bind()
```](/en-us/engine/6000.6/script-reference/unityeditor/uielements/bindingextensions/bind) on the

```
rootVisualElement
```

of an Editor window. This binds all child elements with specified [```
bindingPath
```](/en-us/engine/6000.6/script-reference/unityengine/uielements/ibindable/bindingpath) properties.

Don't call [```
Bind
```](/en-us/engine/6000.6/script-reference/unityeditor/uielements/bindingextensions/bind) from the

```
Editor.CreateInspectorGUI
```

or

```
PropertyDrawer.CreatePropertyGUI
```

override. [```
Bind
```](/en-us/engine/6000.6/script-reference/unityeditor/uielements/bindingextensions/bind) is called automatically on the visual elements that these methods return.

### Call ``` Unbind() ```

The [```
Unbind()
```](/en-us/engine/6000.6/script-reference/unityeditor/uielements/bindingextensions/unbind) method stops the value tracking for the element and all its direct and indirect child elements. In general, you don't need to call [```
Unbind()
```](/en-us/engine/6000.6/script-reference/unityeditor/uielements/bindingextensions/unbind) because tracking stops when a user closes the Inspector or Editor window. Call [```
Unbind()
```](/en-us/engine/6000.6/script-reference/unityeditor/uielements/bindingextensions/unbind) if you must bind elements to different targets in their lifetimes.

If you construct an [```
InspectorElement
```](/en-us/engine/6000.6/script-reference/unityeditor/uielements/inspectorelement) in C# by calling its constructor, binding occurs during the constructor call. If you want to rebind an [```
InspectorElement
```](/en-us/engine/6000.6/script-reference/unityeditor/uielements/inspectorelement) after it has been constructed, you must call [```
Unbind()
```](/en-us/engine/6000.6/script-reference/unityeditor/uielements/bindingextensions/unbind) and then either call [```
Bind()
```](/en-us/engine/6000.6/script-reference/unityeditor/uielements/bindingextensions/bind) explicitly or let a bind operation from a parent create a binding.

### Set binding path

If you call [```
Bind()
```](/en-us/engine/6000.6/script-reference/unityeditor/uielements/bindingextensions/bind) to create the binding, you must set the visual element's binding path to the property name of the object that you want to bind to.

For example:

* If you have the following component script:

  ```
  using UnityEngine;public class MyComp : MonoBehaviour{    [SerializeField]    int m_Count;}
  ```

  To bind your visual element to

  ```
  m_Count
  ```

  , set the binding path to

  ```
  m_Count
  ```

  .
* If you want to bind a visual element to a GameObject's name property, which is

  ```
  m_Name
  ```

  , set the binding path to

  ```
  m_Name
  ```

  .

You can set the binding path in UI Builder, UXML, or with a C# script:

* In UI Builder, enter the binding path in the **Binding Path** field for a visual element in the [Inspector](/en-us/engine/6000.6/manual/uitoolkits/uielements/uibuilder/uib-interface-overview#uibuilder-inspector).
* In UXML, set the

  ```
  binding-path
  ```

  attribute for a visual element. Refer to [Define the binding path in UXML](/en-us/engine/6000.6/manual/uitoolkits/uielements/uie-data-binding/uie-editor-binding/uie-binding-examples/uie-create-a-binding-uxml-bind#binding-path-uxml) for an example.
* In C#, set [```
  bindingPath
  ```](/en-us/engine/6000.6/script-reference/unityengine/uielements/ibindable/bindingpath) from the [```
  IBindable
  ```](/en-us/engine/6000.6/script-reference/unityengine/uielements/ibindable) interface. Refer to [Bind with the binding path](/en-us/engine/6000.6/manual/uitoolkits/uielements/uie-data-binding/uie-editor-binding/uie-binding-examples/uie-create-a-binding-csharp#binding-path-csharp) for an example.

### Call ``` BindProperty() ```

You can call [```
BindProperty()
```](/en-us/engine/6000.6/script-reference/unityeditor/uielements/bindingextensions/bindproperty) to bind an element to a [```
SerializedProperty
```](/en-us/engine/6000.6/script-reference/unityeditor/serializedproperty) directly.

Use this method if you already have a

```
SerializedProperty
```

object, and especially if you traverse the properties of a [```
SerializedObject
```](/en-us/engine/6000.6/script-reference/unityeditor/serializedobject) to build a UI dynamically. Refer to [Bind without the binding path](/en-us/engine/6000.6/manual/uitoolkits/uielements/uie-data-binding/uie-editor-binding/uie-binding-examples/uie-bind-without-bindpath) for an example.

### Bind elements to nested properties

You can bind a visual element to nested properties in the source object. To do so, combine the binding path of an element with the binding path of the first ancestor. Use this method with the following elements:

* [```
  BindableElement
  ```](/en-us/engine/6000.6/script-reference/unityengine/uielements/bindableelement)
* [```
  TemplateContainer
  ```](/en-us/engine/6000.6/script-reference/unityengine/uielements/templatecontainer) (corresponds to the

  ```
  <Instance>
  ```

  tag in UXML)
* [```
  GroupBox
  ```](/en-us/engine/6000.6/script-reference/unityengine/uielements/groupbox)

Refer to [Bind to nested properties](/en-us/engine/6000.6/manual/uitoolkits/uielements/uie-data-binding/uie-editor-binding/uie-binding-examples/uie-bind-to-nested-properties) for an example.

### Receive callbacks when values change

You can create a binding to receive a callback when a bound serialized property changes. To do so, leverage the [```
TrackPropertyValue()
```](/en-us/engine/6000.6/script-reference/unityeditor/uielements/bindingextensions/trackpropertyvalue) extension method, which is available to any

```
VisualElement
```

. This registers a callback that executes when the provided

```
SerializedProperty
```

changes. Refer to [Receive callbacks when a serialized property changes](/en-us/engine/6000.6/manual/uitoolkits/uielements/uie-data-binding/uie-editor-binding/uie-binding-examples/uie-create-a-binding-callback) for an example.

You can also create a binding to receive a callback when any properties of the bound serialized object change. To do so, leverage the [```
TrackSerializedObjectValue()
```](/en-us/engine/6000.6/script-reference/unityeditor/uielements/bindingextensions/trackserializedobjectvalue) extension method, which is available to any

```
VisualElement
```

. This registers a callback that executes when the provided

```
SerializedObject
```

changes. Refer to [Receive callbacks when any properties change](/en-us/engine/6000.6/manual/uitoolkits/uielements/uie-data-binding/uie-editor-binding/uie-binding-examples/uie-create-a-binding-callback-any-properties) for an example.

### Bind custom elements

You can create custom elements and bind them to serialized properties through the [value binding](#value-binding) system.

To create bindable custom elements:

1. [Declare a custom element](/en-us/engine/6000.6/manual/uitoolkits/uielements/uie-structure-ui/uie-custom-controls/uie-create-custom-controls).
2. Inherit the element from

   ```
   BindableElement
   ```

   or implement the

   ```
   IBindable
   ```

   interface.
3. Implement the

   ```
   INotifyValueChanged
   ```

   interface.
4. Implement the

   ```
   SetValueWithoutNotify()
   ```

   method of the

   ```
   INotifyValueChanged
   ```

   interface.
5. Implement the

   ```
   value
   ```

   property accessors of the

   ```
   INotifyValueChanged
   ```

   interface.

Refer to [Create and style a custom control](/en-us/engine/6000.6/manual/uitoolkits/uielements/uie-data-binding/uie-editor-binding/uie-binding-examples/uie-bind-to-list-without-listview#custom-control) for an example.

Note

You can't bind custom data types directly to custom elements because the binding system only allows you to bind an element to a type supported by SerializedPropertyType of

```
enum
```

. This means you can't define a class or structure, for example, a struct called

```
MyStruct
```

, and bind it to an element that implements

```
INotifyValueChanged<MyStruct>
```

. However, you can bind to serializable nested properties of custom data types. This includes polymorphic serialization (when a field uses the [```
[SerializeReference]
```

attribute](/en-us/engine/6000.6/script-reference/unityengine/serializereference)). Refer to [Bind a custom control to custom data type](/en-us/engine/6000.6/manual/uitoolkits/uielements/uie-data-binding/uie-editor-binding/uie-binding-examples/uie-bind-to-custom-data-type) for an example.

## Bind time

Based on the type of UI you create, binding occurs at various times. This is called bind time.

The following table describes the bind time of a control:

| **Condition** | **Automatic bind time (assuming binding path was set)** |
| --- | --- |
| **An ``` InspectorElement ``` constructed in C#** | During the [constructor](/en-us/engine/6000.6/script-reference/unityeditor/uielements/inspectorelement/ctor) call |
| **A child element that is under the return value of  [``` CreateInspectorGUI() ```](/en-us/engine/6000.6/script-reference/unityeditor/editor/createinspectorgui)  or  [``` CreatePropertyGUI() ```](/en-us/engine/6000.6/script-reference/unityeditor/propertydrawer/createpropertygui)  when those methods return** | After  [``` CreateInspectorGUI() ```](/en-us/engine/6000.6/script-reference/unityeditor/editor/createinspectorgui)  or  [``` CreatePropertyGUI() ```](/en-us/engine/6000.6/script-reference/unityeditor/propertydrawer/createpropertygui)  returns |
| **A child element that is under an element when  [``` Bind() ```](/en-us/engine/6000.6/script-reference/unityeditor/uielements/bindingextensions/bind)  or  [``` BindProperty() ```](/en-us/engine/6000.6/script-reference/unityeditor/uielements/bindingextensions/bindproperty)  is called on the parent element** | During the  [``` Bind() ```](/en-us/engine/6000.6/script-reference/unityeditor/uielements/bindingextensions/bind)  or  [``` BindProperty() ```](/en-us/engine/6000.6/script-reference/unityeditor/uielements/bindingextensions/bindproperty)  call |
| **Other** | No automatic binding; you must bind the element or one of its parents manually |

The following are best practices when creating a binding regarding bind time:

* If you create a custom [```
  Editor
  ```](/en-us/engine/6000.6/script-reference/unityeditor/editor) or custom [```
  PropertyDrawer
  ```](/en-us/engine/6000.6/script-reference/unityeditor/propertydrawer), set the elements' binding paths instead of calling [```
  Bind()
  ```](/en-us/engine/6000.6/script-reference/unityeditor/uielements/bindingextensions/bind) or [```
  BindProperty()
  ```](/en-us/engine/6000.6/script-reference/unityeditor/uielements/bindingextensions/bindproperty) on any visual elements that are in the [visual tree](/en-us/engine/6000.6/manual/uitoolkits/uielements/uie-structure-ui/uie-visual-tree/uie-visual-tree) by the end of the body of [```
  CreateInspectorGUI()
  ```](/en-us/engine/6000.6/script-reference/unityeditor/editor/createinspectorgui) or

  ```
  CreatePropertyGUI()
  ```

  . These elements are bound automatically after [```
  CreateInspectorGUI()
  ```](/en-us/engine/6000.6/script-reference/unityeditor/editor/createinspectorgui) or [```
  CreatePropertyGUI()
  ```](/en-us/engine/6000.6/script-reference/unityeditor/propertydrawer/createpropertygui) returns. However, if you add any elements to the visual tree after that point, call [```
  Bind()
  ```](/en-us/engine/6000.6/script-reference/unityeditor/uielements/bindingextensions/bind) or [```
  BindProperty()
  ```](/en-us/engine/6000.6/script-reference/unityeditor/uielements/bindingextensions/bindproperty) to bind them.
* If you create any other type of UI, call [```
  Bind()
  ```](/en-us/engine/6000.6/script-reference/unityeditor/uielements/bindingextensions/bind) or [```
  BindProperty()
  ```](/en-us/engine/6000.6/script-reference/unityeditor/uielements/bindingextensions/bindproperty) regardless of the time at which the elements get added to the visual tree. If you call [```
  Bind()
  ```](/en-us/engine/6000.6/script-reference/unityeditor/uielements/bindingextensions/bind) or [```
  BindProperty()
  ```](/en-us/engine/6000.6/script-reference/unityeditor/uielements/bindingextensions/bindproperty) and bind multiple controls at the same time, set the binding path of each control and then call [```
  Bind()
  ```](/en-us/engine/6000.6/script-reference/unityeditor/uielements/bindingextensions/bind) on the lowest-level parent element that encompasses all the controls. [```
  Bind()
  ```](/en-us/engine/6000.6/script-reference/unityeditor/uielements/bindingextensions/bind) binds the element on which it's called if it has a binding path and recursively binds all its child elements if they have binding paths. To prevent a negative performance impact, don't bind a visual element with the [```
  Bind()
  ```](/en-us/engine/6000.6/script-reference/unityeditor/uielements/bindingextensions/bind) method more than once.

## Bind to a serialized property backing field

When you use an auto-property, the compiler automatically generates a backing field with a name as

```
<PropertyName>k__BackingField
```

. This field is not explicitly visible in your code but can be referenced if necessary, as in binding scenarios.

For example, the following example defines an auto-property

```
SomeProp
```

and serializes it:

```
[field: SerializeField] public float SomeProp {     get;     private set; }
```

The compiler generates the following backing field:

```
[SerializedField]private float <SomeProp>k__BackingField;public float SomeProp{    get => <SomeProp>k__BackingField;    set => <SomeProp>k__BackingField = value;}
```

To bind to

```
<SomeProp>k__BackingField
```

in UXML, you must escape

```
<
```

and

```
>
```

because they're reserved for tags. For example, set the

```
binding-path
```

as follows:

```
<editor:PropertyField name="some-prop" binding-path="&lt;SomeProp&gt;k__BackingField"/>
```
